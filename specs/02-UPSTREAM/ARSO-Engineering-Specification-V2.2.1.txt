下面正式进入 **《ARSO Engineering Specification V2.2.1》**。

这一版不是把旧 V2.2 Engineering 部分重新排版，而是以刚刚冻结的 **Research Specification V2.2.1** 为唯一上游科学规范，将 R4.1 的 Minimum Implementable Core、R5 的 Scientific Kill Tests、R6 的 Revision Decisions 落成真正可以编码和测试的工程合同。

原 V2.2 已经建立了 Artifact Registry、SystemSnapshot、RuntimeEvent、TaskIR→DecisionIR→ExecutionIR、Evaluation/Evidence/Attribution/Hypothesis、Intervention、Validation、Router、Domain/Pattern Pack 等完整平台骨架；同时原 V2.2 的 V0 又把三层 IR、Candidate、DeploymentTransaction 等大量对象列为第一批 mandatory model。 本版最重要的修订就是：**保留长期平台架构，但不再让完整平台绑架第一阶段研究实现。**

# Part I｜Engineering Mission

## 1. 工程目标

ARSO V2.2.1 Engineering 的第一目标不是：

> 建设一个包含 Semantic IR、Memory、Meta-Router、跨域迁移和 Production Deployment 的完整 AI optimization operating system。

第一目标是：

$$
\boxed{
ExistingSystem
\rightarrow
Observable
\rightarrow
Evaluatable
\rightarrow
Diagnosable
\rightarrow
EvidenceBoundedAction
}
$$

具体必须支持：

$$
Run
\rightarrow
Evaluation
\rightarrow
Evidence
\rightarrow
DiagnosticBelief
\rightarrow
Identifiability
\rightarrow
ActionDecision
$$

然后：

$$
ActionDecision=
\begin{cases}
NO\_CHANGE\\
ABSTAIN\\
REQUEST\_EVIDENCE\\
REQUEST\_HUMAN\\
INTERVENE\\
SEARCH\\
STOP
\end{cases}
$$

---

# Part II｜Hard Engineering Invariants

# 3. Reference Task ≠ Mutable System State

正式冻结：

$$
\boxed{
ReferenceTaskSpec
\neq
MutableSystemState
}
$$

Optimizer 不允许通过普通 intervention 修改：

```text
任务成功定义
sealed evaluation target
hard constraint
风险边界
benchmark partition
```

如果必须修改 ReferenceTaskSpec：

> 创建新版本，并视为新的 experiment condition。

---

# 4. Observed ≠ Observable

正式冻结：

$$
\boxed{
MissingEvent
\neq
EventDidNotOccur
}
$$

必须区分：

```text
NOT_OCCURRED
MISSING
NOT_INSTRUMENTED
UNSUPPORTED
REDACTED
SAMPLED_OUT
CORRUPTED
UNKNOWN
```

否则 SC2 无法成立。

---

# 5. Objective ≠ Measurement ≠ Evaluator ≠ Evaluation

原 V2.2 已明确指出 `Objective ≠ Measurement ≠ Evaluator`，但其第一批数据对象主要只冻结了 EvaluationRecord。

V2.2.1 正式落实为四个独立 object。

---

# 6. Diagnosis ≠ Classification

Diagnostic subsystem 必须可以表达：

```text
IDENTIFIED
AMBIGUOUS
INSUFFICIENT_EVIDENCE
UNIDENTIFIABLE
OUT_OF_TAXONOMY
```

不能强迫：

```text
argmax(R0 ... R9)
```

---

# 7. Action ≠ Search

旧 V2.2 Complexity Ladder 将 `NO-OP / REQUEST_EVIDENCE / Local Repair / Single-Lineage / Population / Meta Search` 混在同一层级。原规范确实冻结过该结构。

V2.2.1 正式取消这一 engineering contract。

改为：

$$
\boxed{
ActionDecision
\perp
SearchPlan
}
$$

---

# 8. Artifact ≠ Candidate ≠ Deployment

继续继承 V2.2 已经意识到的三者分离原则，但进一步去除 Artifact 内的 deployment 状态。原 V2.2 已将 Candidate、Intervention、Deployment 分为不同 lifecycle。

---

# 9. Probe 是 Core

`REQUEST_EVIDENCE` 必须有：

$$
ProbePlan
\rightarrow
ProbeResult
\rightarrow
NewEvidence
\rightarrow
Rediagnosis
$$

不能只是 Router enum。

---

# Part III｜Runtime Architecture

# 10. 四个工程平面

V2.2.1 将完整系统明确划分为四个 plane。

## P1｜Execution Plane

业务系统自身执行：

$$
Input\rightarrow ExistingSystem\rightarrow Output
$$

ARSO 不要求接管业务主执行权。

---

## P2｜Diagnostic Control Plane

负责：

```text
Observe
Evaluate
Build Evidence
Diagnose
Assess Identifiability
Decide Action
Probe
Intervene
Validate
```

这是 MIC 核心。

---

## P3｜Experimental Plane

负责：

```text
experiment assignment
paired conditions
randomization
oracle/wrong/no diagnosis
budget matching
sealed-test firewall
lineage
```

这是 SC3 与 R5 Kill Test 的必要基础设施。

---

## P4｜Deployment Plane

负责未来：

```text
Shadow
Canary
Production
Rollback
CAS promotion
```

架构继续保留。

但是：

$$
\boxed{
P4\notin MIC\ V0
}
$$

---

# 11. Data Plane Failure Independence

继续保留 V2.2 的重要原则：

> ARSO Control Plane 故障不得天然导致 Production Data Plane 停机。

MIC 应设计成：

```text
Control Plane unavailable
→ Existing application continues using last stable snapshot
```

研究环境例外可以明确 fail-fast。

# 64. ActionPolicy 示例逻辑

仅作默认 policy，不作为科学真理：

```text
if risk > allowed:
    REQUEST_HUMAN or STOP

elif identifiability == INSUFFICIENT_EVIDENCE:
    REQUEST_EVIDENCE

elif identifiability == UNIDENTIFIABLE:
    ABSTAIN

elif identifiability == OUT_OF_TAXONOMY:
    ABSTAIN or REQUEST_HUMAN

elif no actionable failure:
    NO_CHANGE

elif high-confidence localized repair exists:
    INTERVENE

else:
    SEARCH
```

阈值：

$$
OPEN
$$

$$
\boxed{
\begin{aligned}

&=
Exec(\Theta_t,x_t)\\
\Omega_t
&=
Observe(R_t)\\
Q_t
&=
Evaluate(R_t)\\
E_t
&=
BuildEvidence(R_t,Q_t,\Omega_t)\\
(B_t,H_t,ID_t)
&=
Diagnose(E_t,\Omega_t)\\
a_t
&=
ActionPolicy(B_t,ID_t,\Omega_t,Risk,Budget)
\end{aligned}
}
$$

如果：

$$
a_t=REQUEST\_EVIDENCE
$$

$$
Probe_t
\rightarrow
E_{t+1}
\rightarrow

如果：

$$
a_t=INTERVENE
$$

则：

$$
\Theta_t
\xrightarrow{Intervention}
\Theta'_t
\xrightarrow{VG0\text{-}VG3}
Validation
$$

如果：

$$
a_t=SEARCH
$$

才调用：

$$
SearchPlan
$$

# Part XLIV｜最终 Engineering Definition

> **ARSO Engineering V2.2.1 将第一阶段系统实现定义为一个可以附着在现有黑盒、半黑盒或结构化 AI 系统之上的诊断控制运行时。它通过不可变 Artifact 与 SystemSnapshot 固定执行版本，通过 RuntimeEvent 与 ObservabilityProfile 区分“系统发生了什么”和“优化器能够看到什么”，通过 ObjectiveSpec、MeasurementSpec、EvaluatorBinding 与 EvaluationRecord 分离目标、测量和评价实现，通过 EvidenceBundle、DiagnosticBelief、HypothesisRecord 与 IdentifiabilityAssessment 显式表示当前证据支持的失败解释及其不确定性。系统首先产生 ActionDecision，决定 NO_CHANGE、ABSTAIN、REQUEST_EVIDENCE、REQUEST_HUMAN、INTERVENE、SEARCH 或 STOP，而不把搜索复杂度与控制动作混为一谈。所有 Probe 必须回流形成新 Evidence 并重新诊断；所有 Intervention 必须在 Sandbox Snapshot 上执行，并经过 VG0 Integrity/Safety、VG1 Target Repair、VG2 Protected Regression 与 VG3 Generalization/Replication 验证。Research Experiment 通过 ExperimentAssignment、Information Access 与 Budget 记录支持 Oracle/Predicted/Wrong/None Diagnosis 等严格 matched comparison。完整 TaskIR–DecisionIR–ExecutionIR、Compiler、Domain Pack、Memory、Transfer、Meta-learning 和 Production Deployment 继续作为 ARSO Extended Platform 保留，但不再是 MIC 的强制依赖。**
